Persona Nexus · 部署架構對照

現在的多源架構 → 同源部署

左邊是你現在的樣子：瀏覽器直接連 5 個不同 port，前端得知道每個對外網址。 右邊是同源部署：瀏覽器只認一個網址，反向代理在內部分流。差別不在後端搬到哪，而在「對瀏覽器暴露幾個入口」。

具體要動哪裡

環節現在改成同源後工作量
前端 API 呼叫 寫死 http://localhost:8000 相對路徑 /api/...，不寫主機名 中 · 改 4 個前端
config-loader 設定中心 fetch gateway 拿各服務網址 大多可移除；同源後前端不需知道網址 減法
bootstrap gateway 網址 雞生蛋：得先寫死才連得上 問題消失（相對路徑自動補當前網域） 自動解決
CORS 允許清單 gateway 列 :5173~:5176 同源，多數情況不再需要 減法
反向代理 無（Vite dev server 各跑各的） 新增 Nginx / Caddy 當統一入口 + HTTPS 新元件 · 要學
後端服務 各自 localhost port 綁內網 port，不對外；架構不變 幾乎不動
ai-service + GPU 本機 GPU 跑 26B 一樣綁在你的機器（本次不處理） 不變

重點：你的 api-gateway 已經做了「統一 API 入口」的一半。同源部署要加的，是再往外包一層反向代理， 讓「前端靜態檔」和「gateway API」共用同一個對外網址。後端彼此怎麼連（同機房、同區網）不受影響—— 那是內網的事，決定同不同源的只有「對瀏覽器暴露幾個入口」。
